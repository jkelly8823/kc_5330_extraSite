High Level Overview

Computational Methods (Data Wrangling)

Variant analysis data was obtained via the command line wget for intergrated whole genome sequencing data from the 1000 Genomes Project. The vcf file was filtered on the chromosome column to only chromosome 9, and further filtered to include only the lines within a 50kb window of CDKN2A/B. Similarly, Annovar was downloaded via wget and the structure left unmodified.

From the project folder level, the following commands were used to annotate the filtered file (cdkn2a_2b.vcf). To retrieve and annotate the file with the database of choice, refGeneWithVer the code shown in annovar_table.sh was executed.

Visualization Strategies

This experiment used Python (pandas, matplotlib, pyplot) for statistical analysis and the visualization of variant distribution. The script to create the plot can be found in plotter.py

Regulatory tracks were manually integrated into the UCSC Genome Browser for visual overlap analysis.

Granular Description

GTEx

The genes CDKN2A and CDKN2B were individually queried in GTEx to determine the overall expression profile of these genes in human tissue independent of one another (Figure 2a Figure 2b).

T2D Knowledge Portal

The T2D Knowledge Portal provides a gene-specific variant association with phenotypic data. This database was leveraged to determine the -log10(p-value) of phenotypes including but not limited to T2D, coronary artery disease and (Figure 3).

T2D Knowledge Portal - Variant Sifter

The T2D Knowledge Portal module “Variant Sifter” offers variant annotations across a user-specified genomic region. The genomic region queried was as follows: chr9:21,917,752-22,059,305. This genomic region encompasses the precise genomic location 50kb upstream of CDKN2A and 50kb downstream of CDKN2B. This returned a total of 1,186 variants curated from credible databases and GWAS datasets. The genomic coordinates queried are in the hg19 build for compatibility with the Variant Sifter. The variants were pre-filtered to display only those with a p-value ≤ 0.05. This data is displayed a function of genomic location vs p-value (Figure 4). These variants were exported as a csv for further analysis. This csv was cross-referenced with the GWAS extracted variants to include only those implicated in T2D pathology. This data provided specific allelic information for each variant and confirmed that all of the T2D variants included in this project were SNPs (Table 3).

From the Variant Sifter csv file, the molecular “consequence” was extracted and plotted (see plotter.py) in Figure 5. The molecular consequence is described as the impact of each variant, predicted by the Ensembl Variant Effect Predictor.

All variants are rigorously curated from credible sets and genome-wide association studies. The genomic coordinates are specifically in the hg19 build. I queried the region encompassing CDKN2A 50kB (chr9:21,917,752-22,059,305), and the phenotype "Type 2 Diabetes (T2D)"" which returned a total of 1,186 variants. All 1,186 variants were pre-filtered to ensure a p-value ≤ 0.05, and subsequently exported as a csv for further analysis. The -log10(p-value) for each variant plotted against its genomic location can be visualized in Figure 4.

ANNOVAR - Variant Annotation Pipeline

To annotate curated variants located within a 100 kb region flanking the CDKN2A and CDKN2B genes (50 kb upstream and downstream), I implemented a pipeline centered on ANNOVAR, a widely used tool for annotating genetic variants with functional information. The goal of this pipeline was to identify whether variants in this region were localized in coding or non-coding regions, thereby informing downstream analyses of regulatory disruption.
  1. Defining the Region of Interest
    • The region spanning 50 kilobases (kb) upstream of CDKN2A and 50 kb downstream of CDKN2B was defined using genomic coordinates based on the reference genome.
    • Command line prompts were used to retrieve the vcf file from the 1000 Genome Project.
  2. Variant Curation and Filtering
    • The vcf file contained a high-quality list of curated variants from WGS data. This was filtered via command line prompts to retain only those falling within the defined flanking region.
    • Variants were formatted into the standard ANNOVAR input file (.avinput), which includes chromosome, start, end, reference allele, and alternate allele.
  3. Preparing ANNOVAR Environment
    • ANNOVAR was installed and configured, with relevant databases downloaded using the annotate_variation.pl and convert2annovar.pl scripts.
    • The following ANNOVAR database was used:
      • refGene (or refGeneWithVer) for gene-based annotation
  4. Running ANNOVAR Annotation
    • The table_annovar.pl script was used to annotate the input variants with the selected database.
    • See annovar_table.sh for how the command was formatted.
  5. Post-Annotation Filtering and Summarization
    • The output file was parsed to:
      • Count total annotated variants (n=1,797).
      • Classify variants by their functional category (e.g., exonic, intronic, intergenic, UTR3).
      • Identify variants specifically within CDKN2A and CDKN2B genes.
    • Only 14 of the 1,797 variants were located in coding exons of these genes. The majority were in non-coding regions.
  6. Classification of Variant Locations
    • Using the functional annotations, variants were grouped into categories such as:
      • Intronic ncRNA
      • Intergenic
      • Exonic ncRNA
      • UTR3
      • Exonic (coding)
    • These categories were visualized (see Figure 6) to illustrate the predominance of non-coding localization.
